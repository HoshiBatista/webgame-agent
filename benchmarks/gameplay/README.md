# Независимая проверка сохранённых игр

Команда воспроизводит игровые действия в изолированном Chromium. Для каждой игры она берёт автономный HTML ранее созданной версии и сверяет SHA-256. Сценарии в этом каталоге составлены отдельно от модельных сценариев. Каждый из них связан с полным описанием ожидаемого эффекта, реальными действиями и способом наблюдения.

| Игра | Профиль создания | Примеры проверок |
| --- | --- | --- |
| Змейка | Lite | Поворот с клавиатуры и касанием, рост после еды, столкновения, пауза и повтор |
| Сокобан | Lite и Pro | Стена, допустимый и запрещённый толчки, решение головоломки, состояние после поворота |
| Космический шутер | Экспериментальная Pro | Броня, усиление, победа над флагманом, поражение, сброс при повторе |
| RPG по мотивам «Проклятых земель» | Экспериментальная Pro | Снаряжение и скрытный удар, победа и поражение, клавиатура и сенсорное управление |

19 ноября все пять сохранённых игр прошли 60 сценариев в изолированном Chromium. На их исходное создание и правки пришлось 3641,181 секунды заданий, 2 явных запроса ремонта и 5 запросов edit. Подтверждённая стоимость по журналу составляет $1,496335. У трёх прежних запросов исход неизвестен, резерв по ним составляет $18,84. Сам повторный прогон обращений к модели не делает. [Результаты по каждой игре и профилю](../../docs/evidence/gameplay-benchmark-2026-11-19.json).

В наборе пять конкретных артефактов по 12 сценариев. Доля прошедших игр характеризует эту выборку сохранённых версий. Для оценки качества новой генерации нужно заранее закрепить задачи и учитывать все результаты, включая задания без версии. Селекторы, пути состояния и действия сценариев зависят от реализации игры. Для другой версии автор проверки сверяет их с замыслом и игровыми правилами и привязывает к новому хешу.

## Запуск

Команды выполняются из корня репозитория с установленными зависимостями разработки. Владельцу локальной тестовой БД достаточно один раз экспортировать проверочные версии и учёт их создания. `export` использует настройки подключения Django. Исходники пользовательских игр и исходные ответы моделей остаются вне Git.

```sh
.venv/bin/python scripts/gameplay_benchmark.py export --pack .data/gameplay-pack
.venv/bin/python scripts/native.py prepare
.venv/bin/python scripts/gameplay_benchmark.py run --pack .data/gameplay-pack --report .data/gameplay-report.json
```

На другой машине достаточно передать приватный каталог пакета и использовать тот же Git-коммит. Команда `run` работает без БД и провайдера модели. Если в локальной БД нет исторических версий, понадобится пакет от участника, у которого они сохранены. Параметр `--case snake-lite` у `export` и `run` ограничивает набор. Нативная изоляция требует macOS или Linux с поддержкой штатного валидатора. Контейнерная установка может задать `VALIDATOR_BACKEND=docker` и настроенный `VALIDATOR_SOCKET`.

Для нового исследования скопируйте манифест `suite.json` и передайте его через `--suite` обеим командам. Для каждой отдельной тестовой игры указываются профиль, конечный Run, хеш HTML, сценарии и параметры часов и случайных чисел. Если завершённый Run не создал версию, укажите `artifact_hash: null`. Каждой игре нужен отдельный тестовый чат, чтобы затраты на разные задачи не смешивались. Пакет содержит HTML и числовые показатели на момент экспорта. Модельные промпты, ответы и данные аккаунтов не экспортируются.

## Сравнение и чтение отчёта

Для сравнения моделей используйте один профиль от создания до последней правки в каждом тестовом чате. Отчёт относит затраты всего чата к профилю выбранной конечной версии. В исходном наборе каждый из пяти чатов использовал один профиль.

```sh
.venv/bin/python scripts/gameplay_benchmark.py compare before.json after.json
.venv/bin/python scripts/gameplay_benchmark.py compare report.json report.json --before-profile lite --after-profile pro
```

Первая команда сопоставляет игры по имени кейса и показывает, совпали ли хеш игры, независимые проверки, окружение, часы и seed. Вторая сопоставляет общие семейства игр двух профилей и отдельно перечисляет остальные. В исходном наборе у Lite и обычной Pro сопоставим только сокобан. Сценарии используют элементы управления каждой реализации.

`passed / scheduled` показывает число игр, прошедших все проверки, относительно заявленного набора. Отсутствующий пакет, несовпадение хеша, ошибка инфраструктуры, отсутствие версии и ошибки игровых действий имеют разные статусы и остаются в знаменателе. `checks_passed / checks_total` считает отдельные сценарии. Для любого непрошедшего кейса команда `run` завершается ненулевым кодом.

Учёт охватывает все Run данного тестового чата от начала до выбранной версии. `generation_seconds` суммирует длительность Run, включая очередь и проверки, и исключает промежутки между заданиями. `replay_seconds` показывает длительность текущего независимого прогона с ожиданием валидатора. `repair_calls` считает явные запросы repair/check_repair/visual_patch, `edit_calls` отдельно считает запросы edit. Счётчики операций учитывают запросы с записанным временем отправки. Повторные запросы исходников, звука или других частей входят в разбиение `model_operations` под своими именами. `known_cost_usd` суммирует подтверждённые суммы, `unknown_reserved_usd` отдельно показывает резерв по запросам с неизвестным исходом. Оба финансовых показателя включают исторические записи с пропущенным временем отправки. Нулевая учтённая цена Lite отражает настроенный тариф. `measured_games` указывает, для скольких игр получены финансовые и временные показатели.

Для текущего прогона используется штатный масштаб браузера DPR 1. Некоторые исторические испытания были проведены при DPR 2 с другим окружением. Данные прошлых серий приведены в [матрице Lite/Pro](../../docs/evidence/model-matrix-2026-11-17.json), [проверке змейки](../../docs/evidence/lite-causal-repair-2026-11-17.json), [проверке шутера](../../docs/evidence/pro-creative-2026-11-18.json) и [проверке RPG](../../docs/evidence/pro-staged-code-2026-11-18.json).
