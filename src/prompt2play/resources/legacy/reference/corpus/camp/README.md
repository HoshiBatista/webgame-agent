# Полный рогалик с лагерем: корпус совместимости

Здесь находится проверенный «Пепельный свод» **2.0.1**, адаптированный к четырём
выходным файлам Game Forge. Это записанный разработчиком игровой пример для
регрессионной проверки генератора. Production-провайдер его не читает и не
подставляет вместо ответа на пользовательский запрос.

## Что сохранено и адаптировано

В `original/` лежат все шесть оригинальных модулей без изменений: боевой движок,
кампания, два рендера, музыка и UI. Происхождение и SHA-256 исходного HTML,
модулей и использованных журналов зафиксированы в `provenance.json`.

`build_adapter.py` воспроизводимо объединяет их в `engine.js`, `renderer.js`,
`audio.js`, `ui.js`. Правила кампании и подземелий остаются исходными. Адаптер
добавляет ожидаемые имена классов, монтаж в корневой элемент Forge, очистку
слушателей/RAF, отдельный ключ сохранения корпуса и тестовый мост к той же
кампании, которой владеет обычный UI. Перезапуск кампании использует явное
действие с подтверждением в интерфейсе. Экспорт/импорт обращаются к настоящему
сериализатору и валидатору сохранения.

Исторические внутренние интерфейсы согласованы друг с другом: `audio.js`
содержит исходный композитор музыки, а эффекты создаёт исходный `AshenSound` в
UI. Это пример совместимости с большим существующим проектом; новые авторы
следуют актуальному общему контракту генерации, а не копируют эту структуру.

## Проверяемые сценарии

| Сценарий | Наблюдаемый результат |
|---|---|
| `camp-first-loop` | Задание → законная добыча → доставка → награда → очаг → новый герой с 32 HP, уровнем 1 и XP 0. |
| `camp-pause-reset` | Пауза не двигает правила; оставление вылазки сохраняет банк, здания и прогресс задач. |
| `camp-roundtrip` | Настоящее сохранение восстанавливает правила и RNG; повторение того же продолжения даёт равное состояние. |
| `camp-settlement-once` | Повтор возврата/сдачи и загрузка между ними не начисляют добычу или награду снова. |
| `camp-import-rejection` | Пустой, повреждённый и несовместимый импорт не заменяет текущую кампанию. |
| `camp-unavailable-storage` | Реальный отказ записи/чтения в модели хранилища сохраняет действия в памяти; UI показывает `memory`, затем `saved` после успешной записи. |
| `camp-building-refusal` | Невыполненное задание и закрытая постройка не дают наград и не списывают материалы. |

`first-loop-route.json` содержит **84 публичных действия**, сгруппированных в
27 шагов QA DSL. Для `embers` / Искроведа это 83 боевых/исследовательских
действия и отдельный возврат: 44 золота, 4 дерева, 2 руды и 4 травы. Принятое
задание `watch_1` добавляет 20 золота и 2 дерева, первый очаг стоит 20 золота и
4 дерева. Бот не меняет HP, карту, ресурсы или позиции: он использует обычные
методы кампании, но видит полную карту. Это свидетельство достижимости
механики, а не оценка сложности для человека.

Контракт v3 описывает сроки жизни лагеря, текущего героя, событий и интерфейса,
а также транзакции, квестовые допуски и сохранения. `build_spec.py` сохраняет
воспроизводимую декларацию; `--check` проверяет её совпадение с `spec.json`.

## Запуск проверок

Команды выполняются из корня Game Forge после установки Python-зависимостей:

```bash
python scripts/test_corpus.py
node reference/corpus/run.cjs
npm --prefix reference/corpus/camp ci --ignore-scripts
node reference/corpus/camp/qa/run_ui.cjs
```

При использовании окружения, созданного `forge.py setup`, замените `python`
на `.venv/bin/python`. Последняя команда требует Node.js 22.12+ и двух
зафиксированных зависимостей **только для QA**: LinkeDOM 0.18.12 и
`@napi-rs/canvas` 0.1.100. Они не входят в выдаваемую игру. Отсутствующие
зависимости дают ошибку, а не успешную проверку с пропущенными тестами.

Первый тест выполняет настоящий LangGraph и сборщик с явно записанными
ответами `RecordedCorpusProvider`: число живых вызовов модели равно нулю.
Точный HTML этого прогона находится в поле `artifact_html` отчёта
`docs/evidence/corpus/camp.json`. UI-проверка до исполнения сверяет SHA-256 и
побайтное содержимое скрипта со всеми четырьмя доверенными модулями.

Общий engine-тест выполняет 14 декларативных сценариев четырёх игр, из них
шесть относятся к лагерю. Отказы хранилища явно переданы отдельной UI-проверке.
Она выполняет все семь лагерных деклараций через настоящий UI плюс три
интеграционных сценария: квест/стройка обычными DOM-кнопками, поздний импорт
до получения события `storage` и идемпотентное освобождение ресурсов монтажа.
Результат записывается в `docs/evidence/corpus/camp-ui-runtime.json`.

Воспроизводимость адаптации:

```bash
python reference/corpus/camp/build_adapter.py --check
python reference/corpus/camp/build_spec.py --check
```

## Границы свидетельств

UI исполняется в LinkeDOM с явными моделями фокуса, времени и хранилища и с
CPU Canvas. Это **не браузер и не WebView**, не измерение мобильной
производительности и не прослушивание музыки. Сценарий гонки проверяет
наблюдаемое изменение общего значения перед завершением чтения; он не
доказывает атомарность записи между процессами.

Корпус нужен, чтобы обнаруживать регрессии общих механизмов Game Forge при
работе с существенным игровым проектом. Качество новой генерации проверяется
отдельно живым запуском одинаковых запросов из `reference/evaluation_prompts.json`,
с сохранением успешных и неуспешных результатов.
