# Разбор наработок ML-инженера и конфликтов требований

Проверено 18 октября 2026 года. WebStorm получил доступ первым действием; через Fetch
обнаружена удалённая ветка `origin/develop`. Чтение её файлов выполнялось без checkout
и без слияния с грязной рабочей копией.

Зафиксированная ревизия: `8341af2e1ee22e1274385e9331aa5ff72528800d`.
Основа ветки `origin/main`: `dd961ce`. Просмотрены документы, модельный gateway,
workflow, статические/браузерные проверки, Docker/Compose/nginx и конфигурация CI.
Тесты этой ветки в рамках анализа не запускались; надпись «реализовано» в её матрице
не принята за доказательство поведения новой версии.

## Что сохраняем, адаптируем и исключаем

| Область | Что увидели | Решение для мини-игр |
| --- | --- | --- |
| Стек | FastAPI/SQLAlchemy/Alembic; PostgreSQL 17 в Compose/CI | Django/DRF и Django migrations, PostgreSQL 18+ по согласованному F15; две ORM не нужны |
| Модель | Responses, фиксированный default `gpt-6-luna`, два вызова spec→HTML | Настраиваемый Codex-коннектор сначала, vLLM API затем; один ответ с кодом и кратким замыслом |
| Правки | `generate(...parent_html=...)` возвращает `GeneratedGame.html` целиком | Base-version + точные замены/patch; общий HTML создаёт упаковщик, не повторная генерация |
| Нагрузка | Цель 10 активных запусков, p50 180 с, p95 300 с; расчёт 8,2 вызова/запуск | Это гипотезы старого плана, не измерения и не требования кейса. Новая цель — десятки секунд и один обычный вызов |
| План/роли | Spec, planning, assets, generation, validation, visual review, repair decision | Нет обязательной модельной цепочки; краткий замысел и проверочные действия в ответе автора |
| Версии | Неизменяемые кандидаты, связь с родителем, публикация прошедшего артефакта | Перенести принцип; отдельно владеющие публикации и снимок ремикса |
| Надёжность | Outbox, fences, idempotency, восстановление | Минимальный реализационный набор с реальной проверкой дублей; не переносить все старые сущности |
| Прогресс | SSE с журналом событий | Оставить; команды обычным HTTP, без дополнительного WebSocket-сервиса |
| Контейнеры | API/model/workflow/validator, read-only mounts, egress только модели | Сохранить разделение. Браузерный child sandbox не получает DB/Redis даже если контроллер проверки их использует |
| Preview | Документ обещает отдельный origin, nginx ведёт `/play/` через тот же edge | Отдельный виртуальный хост/origin без cookies; один edge не означает один origin |
| Проверка ввода | `button:visible.first` либо tap по центру; сравнение двух snapshot | Удалить предположение. Использовать управление и ожидаемый эффект конкретной игры |
| Static validation | Regex требует restart, timer loop, фиксированный bridge | Не переносить: отсутствие строки не доказывает неиграбельность, таймер не нужен пошаговой игре |
| Состояние игры | Общие `phase/score/level/lives/objective`, win **и** lose | Не навязывать. По PDF нужен осмысленный исход победы **или** поражения |
| Безопасность | Regex + browser request interception | Полезные ранние сигналы, но не граница. Обязательны контейнерные ограничения и отдельный preview origin |
| Ассеты | Обязательные procedural графика и WebAudio | Графика качественная и компактная, звук по уместности. Отдельный генератор ассетов — вне быстрого пути |
| Аналитика | Агрегация genre/event и передача в spec | Дополнительная возможность после базового продукта; не отдельный модельный шаг по умолчанию |
| CI | Детерминированные проверки отдельно от платных live evals, secret scans | Сохранить. Live запуск только с бюджетом, без автоматического еженедельного расхода |
| Сервисы | Нет отдельного AI HTTP-микросервиса поверх Celery | Сохранить: удалённый vLLM — внешний провайдер, а не причина плодить собственные промежуточные сервисы |

## Что можно взять из GamesForgeEx позднее

Только небольшие независимые части после чтения актуальной версии: транспорт Codex,
применение точных патчей, работа с immutable-артефактами, CSS телефонного preview,
редактирование промптов, диагностика usage. Для каждого переноса — происхождение и тест.

Не переносить планировщика больших проектов, исследователя платформы, схему механик,
правила переаттестации всех ролей, старые миграции, пользовательские данные и инструкции.
GamesForgeEx продолжает развиваться отдельно; этот анализ его файлов не изменяет.
