# Живой пилот Lite v7 после обновления локального валидатора

24 октября 2026. Приложение перезапущено с текущим native-validator. Новый согласованный
пилот Lite закрыт: **20/24 вызовов, 68 мин 14,1 с**, включая предварительные recheck и
независимую оценку. Оставшиеся **4 вызова закрыты**. Модель: существующий API
GameForge → relay → `qwen38`, контракт v7, политика завершения 2. GPU-сервер не менялся.

**Завершение улучшилось: все ответы обработаны приложением у 6/6 новых созданий
против 2/6 в предыдущем v6.** Внешней помощи с квитанциями в этом пилоте не было.
Играбельны по неизменной базовой рубрике **3/6** сохранённых результатов против **2/6**.
Автоматически принятых игр снова **0/6**. Полностью восстановленных наборов проверок
**0/6 попыток**, в том числе **0/2** целевых восстановлений старых рабочих игр.

Известен usage всех 20 вызовов: **70 564 input / 55 042 output tokens**. Активных,
неизвестных и полученных, но неприменённых ответов нет. Локальный нулевой тариф relay
не измеряет стоимость GPU-инфраструктуры.

## Обновление среды и границы

До inference актуализирован локальный нативный валидатор и перезапущены `app`,
`preview`, `worker`, `beat`. Два recheck без модели подтвердили использование текущей
реализации именно настоящим worker, на неизменённых старых исходниках. Hash валидатора:

`901dc92abdd3e1ea058357a9f87adfa2d5db337c9612ad67a11521a757b67cca`

Среда свидетельств — Chromium `145.0.7632.6`, `native-darwin`, мобильный viewport
390×844 и настольный 1280×800. Старый контейнерный backend для этого пилота не выбран.
Исходники генератора, валидатора и измерителя зафиксированы до inference: **44 файла**
плюс hash управляющего сценария. После прогона изменений нет. Закрытые журналы v5/v6
не переписывались. Миграции, настройки модели и GPU-сервера не менялись.

Адаптер, конфигурация и авторизация Codex сохранены; Codex inference не выполнялся.
Есть отдельное ограничение текущей среды: установлен `codex-cli 0.164.0-alpha.11.1`,
а существующий допуск адаптера содержит `0.163.0-alpha.10.2` и `0.163.0-alpha.11.2`.
Поэтому профиль Pro сейчас сообщает `available=false`. Допуск не обходился, версия
CLI не менялась. Сохранность интеграции не является подтверждением её работоспособности
с этой новой версией CLI; нужна отдельная проверка совместимости.

## Восстановление проверок без перегенерации

Два отдельных продолжения используют прежние v5-артефакты, как и в v6. Они не входят
в знаменатель новых игр. Независимая оценка исходных игр после нового recheck:
grid — **7/7** настоящих сценариев, memory — **3/3** плюс снимки совпадений и
закрытия несовпадений. Оба исходника остаются играбельными по базовой рубрике.

У целевого grid модель вернула `unchanged` с непустым `checks`. Контракт отклонил
ответ как `invalid_unchanged`; приложение завершилось `needs_attention`, usage сохранён.
У целевого memory получен допустимый `unchanged`. Модель сослалась на отсутствие
DOM-индикаторов ходов/победы, хотя они есть в исходнике и независимый тест их читает.
Ответ обработан, но проверки не восстановлены. Ни один случай не создал нового кода.

| Попытка check_repair | Обработка | Код | Результат проверок |
| --- | --- | --- | --- |
| Старый grid | отказ контракта учтён | сохранён | `invalid_unchanged` |
| Старый memory | допустимый `unchanged` | сохранён | исходный набор не восстановлен |
| Первый новый grid | новая Revision сценариев | тот же hash | 1/5 фактов прошёл; 4 несовпадения |
| Первый новый snake | новая Revision сценариев | тот же hash | 2/5 прошли; набор `unverified` |
| Первый новый memory | новая Revision сценариев | тот же hash | 1/6 прошёл; набор `unverified` |
| Повторный memory | новая Revision сценариев | тот же hash | 3/4 прошли; начало `unverified` |

Во всех **4** применённых дочерних наборах сценариев побайтово сохранены files,
HTML/hash, design и title. В последнем memory модель исправила реальные касания:
ход и победа подтверждаются уже приложением. Но добавленный `required_start`
читает `overlay.hidden` через безопасный наблюдатель `state`; такого экспортированного
поля нет. Поэтому весь набор не подтверждён. Отдельный независимый сценарий нажимает
Start и читает существующее `state.status`: начало работает.

У первого grid модель оставила обычный `click` с дробными координатами вместо
`click_fraction`, с ошибочными наблюдениями. Независимые касания правильных центров
дают **8/8**. Таким образом, процесс применения ремонта сценариев работает, но качество
его результата остаётся недостаточным. Пересмотренные моделью сценарии сами по себе
не открывают автоматическое принятие. У первого grid сохраняется `check_review_required`:
независимо рабочая игра не стала подтверждаемой через текущий результат приложения.

## Независимая играбельность и дефекты

Проверки выполнялись настоящими касаниями/клавишами в изолированном native Chromium,
без изменения игрового кода, состояния, seed, времени или приложения. Состояние читалось
через допустимые собственные поля, без вызова пользовательских getters.

**Первый grid — играбелен.** Пустое поле, настоящий центральный ход, чередование,
запрет занятой клетки, победы X/O, ничья, запрет ходов после победы и сброс: **8/8**.
Кнопки/поле доступны в мобильном размере. Некоторые подписи смешивают локализации;
это не полный визуальный или языковой приёмочный тест.

**Первый snake — не проходит мобильную рубрику.** Клавиатура действительно поворачивает
движущуюся змейку; запрещён разворот назад, столкновение завершает партию. Но кнопки
Left и Down имеют один прямоугольник `(164,359,56,56)`: Down перехватывает касание Left.
После проигрыша Up также перекрывает центр Restart. Скриншот и реальный hit-test
подтверждают проблему. Это дефект игрового CSS, а не отказ среды проверки. Победа
после пяти яблок независимо не подтверждалась; базовая игра уже провалила доступность.

**Первый memory — после двух ремонтов играбелен.** Первая версия падает на `ctx`,
следующая — на чтении отсутствующей карточки. Обязательные runtime gates выполняются,
хотя все исходные checks имеют категорию regression и семантически неполны.
Приложение выдаёт привязанный к отчёту/hash `code_repair_basis`, затем два ограниченных
ремонта меняют только `game.js`. Весь список checks в прежнем порядке, design и title
сохранены. Вторая правка также меняет ошибочное перемешивание для каждой карты
на единую перемешанную колоду с двумя парами.

Получено **6/6** независимых проверок, включая две мобильные и одну настольную победу,
закрытие несовпадения и сохранение совпадения. Используется перебор всех шести
допустимых пар касаний с ожиданием, который покрывает каждую раскладку двух пар,
без записи состояния. Дополнительный дефект вне прежней базовой рубрики:
после победы Restart сбрасывает текст, но не перерисовывает Canvas до следующего
действия; остаются видны старые открытые карты. Базовая играбельность не означает
готовность без ошибок.

**Повторный grid — неверно объявляет победителя.** Настоящая колонка X даёт
«Победитель: O», диагональ O — «Победитель: X». Из **7** независимых сценариев
проходят **5**, оба правильных победителя не подтверждаются. Скриншот X-линии
с подписью O сохранён. Код переключает текущего игрока до формирования подписи.
Ничья, запрет занятой клетки и сброс работают; основное требование исхода нарушено.

**Повторный snake — не запускается после трёх ремонтов.** Все четыре версии дают
`Assignment to constant variable.`. Настоящий Start оставляет `state.phase=idle`;
управление и столкновение не становятся рабочей партией. Проблемная строка остаётся:
локальный `const offsets=[]` затем переназначается при рисовании головы. Первый ремонт
ошибочно объясняет сбой запретом менять свойства объекта `const state` и переписывает
рабочие обращения к состоянию. Последующие правки снова меняют представление состояния,
но оставляют саму ошибку. Общий лимит соблюдён, результат — `repair_exhausted`.

Все три ремонта меняют только `game.js`, сохраняют checks/title. Один дополнительно
меняет формулировку design.summary с «простым дублем» на «простым управлением»;
нельзя утверждать побайтовую неизменность design во всех ремонтах кода.

**Повторный memory — играбелен с первого исходника.** **8/8** независимых проверок:
Start, четыре карты, настоящее открытие, повторное касание той же карты,
увеличение ходов после двух карт и победы на двух свежих мобильных и одной настольной
партии. Три отдельных снимка показывают закрытое несовпадение после 850 мс;
победный снимок — обе открытые пары. Настоящий Restart возвращает четыре закрытые
карты. Небольшой визуальный дефект: карты частично перекрывают заголовок/HUD сверху;
касания и исход доступны. Ремонт менял только сценарии.

## Неполные исходники и полезность диагностики

Три create-ответа корректно отклонены до создания кандидата. В первом есть только
обрывок HTML/CSS, нет выполняемой реализации. Два ответа повторного grid содержат
`game.js` длиной **4333** и **6496** байт, без единого переноса строки, начинающийся
с `//`: весь скрипт — комментарий. Сверка с raw JSON подтверждает те же исходные байты;
упаковщик не склеивал строки. Нативный браузер показывает пустой прозрачный Canvas
и неизменную подпись после настоящего Start/касания клетки. У обрывка HTML нет
интерактивной поверхности. Эти отклонённые ответы не увеличивают число созданных игр.

В повторном snake диагностика указывает line=1, column=4794, но фокусный
`source_excerpt` содержит только первые **500 символов** строки и не включает `offsets`.
Фрагмент около реальной колонки сразу показывает переназначение const. Полный модуль
у модели присутствует; этот случай не доказывает, что обрезка была единственной
причиной неудачи. Он показывает конкретную потерю полезной локализации, одновременно
с неверным рассуждением модели о JavaScript. Смещение колонок после неудачных
переписываний также мешает распознать повтор того же дефекта раньше общего лимита.

## Следующие приоритеты

1. Фокусировать диагностику вокруг фактической browser-колонки, учитывая UTF-16,
   а не только начало длинной строки. Добавить регрессию с минифицированной строкой
   и не-ASCII до ошибки. До нового пилота проверить, что строка `offsets` попадает в
   передаваемое свидетельство. Усечение и точная исходная позиция должны оставаться явными.
2. Продолжить запланированную вторую поставку компактного Lite-профиля: маленькие
   исходники с переносами, короткие сценарии реального ввода, явная подготовка Start,
   дробные координаты только соответствующим действием, существующие безопасные
   наблюдения. Не ослаблять рубрику и не подменять ошибочные ожидания ради зелёного статуса.
3. Проверить маршрут пользовательского завершения для рабочего артефакта с плохими
   сценариями: сохранённый результат должен быть доступен для понятной проверки/продолжения
   с актуальными gates. Доказанные ошибки игры и неуверенность проверочного набора
   должны сохранять разные основания решения. Дополнительно проверить обнаружение
   перекрывающихся кнопок после Start и повтор одинакового runtime-дефекта после ремонта.

Это предложения по результатам измерения; во время пилота генератор не исправлялся.
Работу по совместимости установленного Codex CLI нужно провести отдельно, сохраняя
защитные ограничения адаптера и авторизацию.

## Протокол, свидетельства и ограничения

Новый журнал имеет собственный бюджет 24 вызова / 90 минут. До inference установлен
предел новых отправок **75 минут**, оставляющий время на квитанции и оценку; общий
предел — 90 минут. Все запланированные случаи закончились раньше обоих пределов.
Прочие правки игр и дополнительные повторы не запускались. Таймер не сбрасывался.

До inference исправлено только чтение измерителем поля environment из сериализованного
API-отчёта; старый/новый hash сценария записаны при **0 вызовов**, без изменения генератора.
В независимом тесте отклонённых источников первоначальная проверка против предполагаемой
надписи отброшена: окончательный тест сравнивает реальный текст до/после ввода через
`changed`. Оба комментарийных скрипта его проваливают. Это исправление измерения,
не дополнительный ремонт игры и не модельный вызов.

Сводные hashes, состояния, usage, времена, все Revision и критерии доступны в
[машиночитаемых свидетельствах](evidence/lite-v7-pilot-2026-10-24.json).
Сравнение — с [отчётом v6](lite-v6-pilot-2026-10-24.ru.md).
Приватные исходники, ответы, квитанции и браузерные снимки остаются в
`.data/lite-v7-pilot-20261024*` и `.data/lite-v7-independent/`.

Точные веса/квантование и неявные sampling relay не раскрывает; `qwen38` — известный
alias, а не подтверждённая ревизия весов. Это малая диагностическая выборка,
не контролируемое A/B, не p95, не сравнение с OpenAI и не физический WebView.
Сквозная обработка отложенных ответов подтверждена, но отсутствие всех возможных
гонок или устойчивое качество по этой выборке не доказывается.

После оценки временный сервер просмотра на 8014 остановлен, его вкладка закрыта.
Основные app/preview/worker/beat оставлены работающими. Авторизация Codex и GPU-сервер
не затрагивались; новые вызовы по закрытому бюджету не разрешены.
