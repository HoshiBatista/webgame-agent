# Живой пилот Lite после исправления завершения

24 октября 2026. Три фиксированных запроса через существующий GameForge API → relay →
`qwen38`, политика завершения 2, контракт генерации v4. **Обработка завершилась во всех
трёх случаях, но рабочей игры не получилось ни в одном.** Исправление завершения
не устранило недостатки самой генерации и ремонта.

Разрешено до 24 вызовов и 90 минут. Выполнено **10 вызовов**, от первого запуска до
последнего решения **17 мин 38,9 с**; пилот закрыт вместе с независимой оценкой через
19 мин 30,4 с. Оставшиеся 14 вызовов не использованы и автоматически не возобновляются.
GPU-сервер, его исполнитель и конфигурация не изменялись. Облачное приложение не
обновлялось. Локально применены миграции 0008/0009 и запущен native-validator в изоляции ОС.
Путь Codex сохранён; новых вызовов Codex в этом бюджете нет.

Малые правки явно пропущены для всех трёх запросов: нет независимо проверенной принятой

## Что подтверждено

1. Задания доходят до конечного состояния. В интерфейсе проверено отсутствие активной
   генерации у завершённого Run, наличие причины остановки и сохранённого кандидата.
2. Змейка остановлена после двух одинаковых результатов вместо расходования всего
   потолка из четырёх вызовов. Это наблюдение остановки, а не измеренное A/B-ускорение.
   Исходный код задаёт голову `(2,7)`, тело `(3,7),(4,7)` и движение вправо: первый
   синхронный шаг сталкивается с собственным телом. Ремонт поменял обработчик клавиш
   и ускорил шаг с 450 до 300 мс, но не устранил первопричину. Браузер воспроизвёл
   немедленное поражение и у исправленной версии.
3. В memory приложение сохранило явную коррекцию `text → text_number`. Отсутствие
   Canvas осталось блокирующим: исправление представления проверки не объявило игру
   рабочей. Ручное принятие всех трёх результатов запрещено.
4. У grid и memory обнаружен общий тупик: неполный первоначальный ответ уже становится
   кандидатом, затем patch-ремонт отвергает попытку полностью заменить его крошечный
   HTML (`whole_file_patch`), после чего модель ошибается в `old_text`
   (`ambiguous_patch`). Все исходные дефекты и ошибки применения сохранились отдельно.

## Решение о следующем изменении

Для этапа D первым нужен **структурный ремонт и различение неполного первоначального
ответа и настоящего игрового кандидата**. Расширять runtime до этого измерения не нужно.

- Неполные исходники при создании должны получать отдельную причину и корректирующий
  create-шаг в прежнем общем бюджете. Чистая HTML-заглушка не должна загонять создание
  в контракт локального ремонта существующей игры. Не отбрасывать такой ответ:
  сохранять оригинал, usage и причину отказа.
- Для настоящего кандидата проверить ограниченную замену небольшого файла/модуля
  с точным hash базы и неизменными требованиями. Сохранить атомарность, отмену,
  восстановление и последнюю принятую версию. Не разрешать полную перезапись рабочей
  игры под видом малой пользовательской правки.
- Уменьшить нагрузку единого ответа «замысел + весь код + сценарии»: в двух случаях
  модель выдала сценарии без реализации. Раздельный контракт следует проверять отдельно;
  этот пилот ещё не доказывает, что дополнительный модельный шаг улучшит результат.
- После изменения повторить те же запросы и независимые рубрики. Только затем
  проверять малые правки и выбирать необходимость runtime/двухшаговой генерации.

Первые два пункта исходной работы — завершение и семантика проверок — реализованы.
Измерение выявило границы этих исправлений; перечисленные изменения генератора
относятся к следующему этапу и ещё не включены.

## Воспроизводимость и ограничения

Сводные данные: [машиночитаемое свидетельство](evidence/lite-completion-2026-10-24.json).
Приватные запросы, канонические ответы, диагностика, точные HTML/исходники и оценки
хранятся в `.data/lite-completion-20261024*`; исходные ответы также сохранены в БД.
Скрипт `scripts/live_eval.py` сохраняет общий таймер/бюджет, резервацию до отправки,
идемпотентный ключ, паспорт исходников и отдельные оценки. Закрытый пилот нельзя
возобновить для расходования остатка; `--phase report` работает без inference.

Для всех вызовов сохранены hashes prompt/schema, пределы 32 768 контекста и 16 384 ответа.
Зафиксирован alias `qwen38`; точные веса/квантование и неявные параметры sampling API
не раскрывает. Генератор и валидатор во время пилота не менялись. Это диагностический
прогон из трёх задач, **не контролируемое сравнение до/после, не сравнение с OpenAI,
не оценка p95 и не испытание физического WebView**. В этой выборке нет работоспособной
игры с ложным отказом; соответствующие случаи подтверждены регрессиями на тестовых играх.
