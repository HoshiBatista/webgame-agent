# GameForge: инструкция для локального запуска командой

Проверяемая конфигурация на 23 октября 2026 года: локальный GameForge в Docker,
облачное HTTPS-реле `https://129.101.114.59`, модель `qwen38`.
Инструкция и шаблон конфигурации не содержат рабочих паролей или токенов.

## Что получится

На вашем компьютере будут интерфейс, база истории, очередь и браузер проверки игр.
Генерацию выполняет уже установленная удалённая модель. Нужны интернет и персональный
токен реле. GPU, VPN, SSH-доступ к серверам и установка модели на ваш компьютер не нужны.
Реле и GPU-исполнитель локально устанавливать тоже не нужно.

Доступ к LLM и качество результата — разные проверки. В текущей версии доставка ответов
работает, но последний тест змейки не прошёл проверку JavaScript после четырёх вызовов.
Это рабочий стенд разработки, а не обещание успешной генерации любой игры.

## 1. Получите исходники и персональный доступ

Исходники берём из Git, архив не нужен:

```sh
git clone --branch mini-games https://github.com/HoshiBatista/webgame-agent.git GameForge
cd GameForge
```

Понадобится доступ GitHub-аккаунта к репозиторию. Администратор отдельно передаёт каждому
участнику его файл `participant-N.env`. Это **секретный персональный доступ к реле**,
а не полная конфигурация приложения. Не кладите этот файл в Git или общий чат.
Перенесите значения из него в свой `.env`, заменяя соответствующие строки без дубликатов.
Секрет Django, пароль локального пользователя и настройки БД каждый задаёт самостоятельно.

**Можно работать полностью без Docker:** используйте [инструкцию macOS / Linux / WSL2](native-local-setup.ru.md).
Ни VPN, ни SSH-доступ к облачному/GPU-серверу участнику не нужны. Ниже — вариант через Docker.

## 2. Подготовьте Docker

- macOS: запущенный Docker Desktop.
- Windows: Docker Desktop в режиме Linux containers с WSL2; команды ниже выполняйте
  в терминале Linux внутри WSL. Храните распакованный проект в домашнем каталоге WSL.
- Linux: Docker Engine и плагин Docker Compose; ваш пользователь должен иметь
  разрешение обращаться к Docker.

Установочные страницы: [Docker Desktop](https://docs.docker.com/desktop/),
[Docker Engine](https://docs.docker.com/engine/install/),
[Compose plugin](https://docs.docker.com/compose/install/linux/).

Проверьте:

```sh
docker version
docker compose version
```

Первая сборка скачивает образы и зависимости, включая Chromium. Нужны свободное место
на диске и стабильный интернет на время установки. Python, Node.js, PostgreSQL и Redis
на хост устанавливать не требуется: они входят в контейнерную сборку.

## 3. Создайте конфигурацию

Все команды выполняются в клонированном каталоге, рядом с `manage.py` и `compose.yaml`.

Создайте `.env`, не перезаписывая существующую:

```sh
if [ -e .env ]; then
  echo '.env уже существует: отредактируйте его, не перезаписывайте.'
else
  cp .env.team.example .env
  chmod 600 .env
fi
```

Откройте `.env` в редакторе. Замените **все четыре** значения `CHANGE_ME`:

| Переменная | Что поставить |
| --- | --- |
| `DJANGO_SECRET_KEY` | Новый случайный секрет этой установки |
| `DJANGO_SUPERUSER_PASSWORD` | Уникальный пароль локального входа, минимум 10 символов |
| `POSTGRES_PASSWORD` | Случайный пароль из шестнадцатеричных символов `0-9a-f` |
| `GAMEFORGE_RELAY_API_KEY` | Ваш персональный `client`-токен реле |

Для первых трёх значений можно получить независимые случайные строки командой ниже.
Она печатает **ваши локальные секреты**: скопируйте их в `.env`, не отправляйте вывод в чат.

```sh
docker run --rm python:3.12-slim python -c 'import secrets; print("DJANGO_SECRET_KEY=" + secrets.token_hex(32)); print("DJANGO_SUPERUSER_PASSWORD=" + secrets.token_hex(16)); print("POSTGRES_PASSWORD=" + secrets.token_hex(24))'
```

Логин `DJANGO_SUPERUSER_USERNAME=admin` можно изменить до первого запуска.
Остальные значения шаблона уже настроены на наш облачный сервер:

```dotenv
CONTAINER_PROVIDER=relay
CONTAINER_MODEL=qwen38
GAMEFORGE_RELAY_URL=https://129.101.114.59
GAMEFORGE_VLLM_JSON_MODE=json_schema
GAMEFORGE_VLLM_CONTEXT_CHECK=server
GAMEFORGE_MAX_REPAIR_ATTEMPTS=3
GAMEFORGE_BUDGET_USD=50
GAMEFORGE_PRICES_JSON={"qwen38":{"input":0,"cached":0,"output":0,"context_window":32768,"max_output_tokens":16384}}
```

В Docker провайдера выбирает именно `CONTAINER_PROVIDER`, а не `GAMEFORGE_PROVIDER`.
Без этой настройки Compose по умолчанию использует демонстрационный `fake`.
Адрес реле указывается **без** `/v1` и `/bridge/v1`. Старый прямой прокси `/v1`
не используется. `server` и указанные лимиты относятся к нашему проверенному backend;
их нельзя автоматически переносить на другой сервер.

Нулевые цены означают нулевую расчётную стоимость токенов своей модели в журнале
GameForge; GPU-время и аренда сервера всё равно расходуются. Верхний предел исправлений —
три дополнительных вызова после первого, а не бесконечная генерация.

`GAMEFORGE_RELAY_API_KEY_FILE` в этой Compose-поставке не подключён: используйте
`GAMEFORGE_RELAY_API_KEY` в закрытой `.env`. Ключ передаётся только контейнеру worker,
не браузеру, не сборке фронтенда и не контейнеру, исполняющему игру.

## 4. Соберите и запустите

```sh
docker compose config --quiet
docker compose up -d --build
docker compose ps -a
docker compose logs --tail=50 init worker validator
```

Проверка `config --quiet` проверяет структуру конфигурации, но не действительность токена.
Не используйте обычный `docker compose config` для пересылки диагностик: он раскрывает
подставленные секреты.

Сервис `init` применяет миграции и создаёт начального администратора. Его статус
`Exited (0)` нормален. `db`, `redis`, `app`, `preview`, `worker`, `beat`, `validator`
и `edge` должны работать. Отдельно `scripts/validator-start.sh` запускать не нужно:
Compose уже создаёт свой браузер проверки.

Откройте **http://127.0.0.1:8080/** и войдите с логином/паролем из `.env`.
Приложение открывайте именно через `127.0.0.1`: игровой предпросмотр использует другой
host `localhost:8081`, чтобы не получать cookie приложения. На корне
`http://localhost:8081/` ответ 404 ожидаем — игра открывается по отдельной ссылке.

Порты 8080 и 8081 должны быть свободны. Если они заняты, не завершайте неизвестные
процессы: согласуйте другую конфигурацию портов и обоих origin с разработчиком.
Одной замены порта в адресной строке недостаточно.

## 5. Проверьте установку без генерации

```sh
curl --fail http://127.0.0.1:8080/api/health/
docker compose exec -T app python manage.py check
```

Проверка отдельного браузера:

```sh
docker compose exec -T worker python -c 'from validation.service import environment_identity; value=environment_identity(); assert not value.endswith(":unavailable"), value; print("Validator OK")'
```

Проверка TLS и персонального токена реле:

```sh
docker compose exec -T worker python -c 'from generation.providers.relay import configuration; from generation.relay_api.client import Client; url,token=configuration(); client=Client(url,token); result=client.call("GET","/health"); client.close(); assert result.get("protocol")==1; print("Relay TLS/auth OK")'
```

Эти команды не отправляют запрос модели. Успех последней проверки подтверждает доступ
к реле, но не свободную GPU и не качество сгенерированной игры.

После успешных проверок создайте в интерфейсе **один** небольшой тестовый запрос.
В выборе провайдера должно быть `relay`, модель — `qwen38`. Дождитесь финального статуса.
Несколько участников используют общий исполнитель, поэтому очередь нормальна.
Если результат не прошёл проверки, это не обязательно ошибка установки: откройте
«Подробности запуска» и передайте ID задания и текст ошибки владельцу проекта.

## 6. Остановка, повторный запуск и сохранение истории

Закрытие вкладки не останавливает уже выполняющийся запрос. После возвращения откройте
тот же чат. Локальные сервисы должны работать, чтобы получить и проверить результат.
Если компьютер уснул, возобновление зависит от запуска Docker и контейнеров.

Перед плановой остановкой дождитесь окончания активных заданий:

```sh
docker compose stop
```

Повторный запуск, в том числе после перезапуска Docker:

```sh
docker compose up -d
```

История и учётные записи находятся в Docker volumes. Обычная остановка их сохраняет.
**Не выполняйте `docker compose down -v` или очистку volumes:** это удаляет локальные данные.
Не меняйте имя Compose-проекта (`gameforge-mini`) и не запускайте вторую копию с тем же
именем на одном компьютере. Для независимых копий нужны отдельные volumes, порты и origin.

Изменение `.env` применяется через `docker compose up -d`, а не простым `restart`.
Уже созданный пароль администратора или PostgreSQL от этого не меняется.
Если забыли пароль локального администратора:

```sh
docker compose exec app python manage.py changepassword admin
```

Укажите свой логин вместо `admin`, если меняли его. Команда интерактивно запросит новый пароль.
Смена владельца токена реле при незавершённых заданиях лишит установку доступа к их ответам;
сначала завершите задания или согласуйте ротацию ключа с администратором.

## 7. Обновление и диагностика

Дождитесь окончания заданий, сохраните резервную копию БД и `.env`, остановите сервисы.
Сохраните свои правки и выполните `git pull --ff-only`. Не заменяйте `.env` шаблоном.
Сохраните имя Compose-проекта и существующие volumes. Затем:

```sh
docker compose build
docker compose run --rm init
docker compose up -d
```

`run --rm init` явно выполняет миграции новой версии. До обновления с изменением схемы БД
согласуйте резервную копию с разработчиком. Не заменяйте `.env` новым шаблоном целиком.

| Симптом | Что проверить |
| --- | --- |
| Docker недоступен / permission denied | Запущен ли Docker и разрешён ли доступ вашему пользователю |
| `init` завершился с ошибкой | `docker compose logs --tail=100 init`; заполнены ли секреты и пароль ≥10 символов |
| Не открывается сайт | `docker compose ps -a`, порты 8080/8081, `docker compose logs --tail=100 edge app` |
| Работает `fake`, а не модель | В `.env` нужны `CONTAINER_PROVIDER=relay`, `CONTAINER_MODEL=qwen38`, затем `up -d` |
| 401/403 от реле | Нужен действующий персональный client-токен; попросите владельца проверить его роль |
| Ошибка сертификата / timeout | Проверьте время компьютера и исходящий HTTPS; не отключайте проверку TLS |
| Ждёт исполнителя | Реле доступно, но GPU-исполнитель занят или недоступен; сообщите ID задания администратору |
| Ошибка контекста до отправки | Проверьте лимиты `GAMEFORGE_PRICES_JSON` и `GAMEFORGE_VLLM_CONTEXT_CHECK=server` |
| Ошибка JavaScript или формата игры | Это результат работы модели; сохраните ID и отчёт, не переустанавливайте Docker |

Для диагностики достаточно ID задания, статуса, текста ошибки и ограниченного фрагмента
логов. Не отправляйте `.env`, токены, полную конфигурацию Compose или дамп базы в общий чат.

## Для владельца реле: выдача доступа

В существующем контейнере реле оператор выполняет его штатный CLI, например:

```sh
python -m llm_relay.admin add-token client gameforge-alice --output /data/gameforge-alice.token
```

Это **команда внутри relay-контейнера на облачном сервере**, не команда на ноутбуке участника
и не на GPU. Имя `gameforge-alice` заменяется уникальным именем участника; выходной файл
должен быть новым. CLI создаёт закрытый файл с токеном. Передайте содержимое адресату
приватно. Для отзыва конкретного старого ключа используется `revoke client PRINCIPAL --token-file FILE`; полный отзыв principal затронет все его ключи.

Доступ на серверы остаётся у операторов. Для обычной работы команды достаточно этой
инструкции, исходников из Git и персонального client-токена.
