## Периодические ревью

Первое ревью исправило адресацию draft, переключение edit в check_repair и режим
отправки в Studio. Второе — сохранение профиля в remix/identity, обязательную регистрацию
модуля, ложные доказательства по декоративному состоянию и float в Playwright clock.
Положительные и отрицательные fixtures включают occupied/winner, отсутствие реального
движения, перекрытие управления, константный outcome, resize и blur.

Основная серия C исполнялась на неизменном manifest **47 файлов**. Найденные во время
неё исправления сначала проверены в отдельной временной копии без inference, затем
перенесены в checkout после завершения допущенных живых запросов:

1. **Выбор малого модуля:** допустимые пути фильтруются до выбора по findings.
   Первый frame ошибки factory может указывать на защищённый runtime.js, следующий
   finding — на game.js; compact теперь выбирает game.js. Авторский runtime.js полного
   профиля разрешён. Маленький helper не подменяет большой основной модуль.
2. **Удаление старых игр:** пустые чаты прежнего контракта скрываются, включая уже
   лишившиеся Revision. Смешанный чат с текущим Run/Revision и новый пустой чат сохраняются.
   Финансовые связи, пользователи и исходные ответы не удаляются.
3. **Одна строка:** явный запрет CR/LF/U+2028/U+2029 после структурной валидации закрывает
   допуск завершающего LF через Python `$`. Байты кода не исправляются автоматически.
4. **Create status:** невозможный `unchanged` удалён из схемы create; edit/repair/
   check_repair сохраняют этот исход. Регрессия воспроизводит потраченный на него ответ.
5. **Совместимость regex:** ограничения Unicode перенесены из отрицательного класса
   декодера в приложение. Передаётся ASCII-класс; регрессия допускает круглые скобки.
   Известный дефект XGrammar согласуется с raw-ответами пилота, но серверная версия
   не установлена. Новая живая проба оборвалась до первого байта; доказательства
   успешного исправления на реальной модели нет.
6. **Saved response recovery:** сохраняются title/design и model_profile, передаётся
   сохранённый code_repair_basis после сверки с актуальным свидетельством. Устаревший
   basis отклоняется; scope_refusal не вызывает KeyError. Восстановление не разрешает
   inference и не переписывает исходный расход/ответ.

Все шесть групп имеют регрессии, воспроизведённые до исправления. После закрытия
бюджета ревью отчёта выявило отрицательное «время генерации» для унаследованного
check_repair-кандидата: существующая игра теперь явно помечена, её создание не считается
новой генерацией. Новая регрессия прошла; после этого модельных вызовов не было.

## Решение по внедрению

Исправления A/B и замечания ревью реализованы и проверены локально. **Не включать
compact по умолчанию на основании этого опыта:** с string он сократил объём output,
но не увеличил число играбельных игр; checks остаются слабым местом. C дал измерения
и диагностировал отдельный дефект lines, однако финальный живой повтор после исправлений
не выполнен. Для него потребуется отдельный новый согласованный бюджет и работающий
исполнитель. Закрытые 15 вызовов не переносятся.
