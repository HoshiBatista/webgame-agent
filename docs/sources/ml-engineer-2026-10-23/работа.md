# Детализация проекта с точки зрения клиента и разработчика

## Лендинг для неавторизованного пользователя

Современный геймифицированный лендинг с яркими ассетами на мягком белом фоне.
Все ассеты реализуются средствами HTML, CSS и TypeScript. Переключения темы нет.
Футер аккуратный и спокойный. Этот лендинг доступен только неавторизованным пользователям.

## Авторизация и учётные записи

Из хедера и ещё из одного места на лендинге можно перейти к форме авторизации.
Регистрации нет. Форма оформлена в тех же мягких белых тонах и сохраняет игровую
атмосферу. Её дополняют пиксельные изображения на фоне: змейка, Pac-Man
и узнаваемые пиксельные игры нулевых.

В Docker-конфигурации backend предусматривается отдельная идемпотентная команда
первоначального создания административной учётной записи с данными из `.env`.
Она запускается после миграций и не создаёт повторную запись, если пользователь
с таким username уже существует.
Через неё создаются демонстрационные аккаунты.
У каждого аккаунта должно быть **уникальное имя пользователя без учёта регистра**.

## Интерфейс авторизованного пользователя

Текущая итерация оформляется в стиле Билайна: жёлтые акценты, чёрная типографика,
светлый фон, округлые элементы и полосатый круглый знак средствами CSS.
Переключение светлой/тёмной темы остаётся дальнейшим улучшением.

URL авторизованной части не имеют дополнительных префиксов.
Адрес главной страницы для авторизованного пользователя: `https://digsy.ru/`.

## Чаты и генерация игр

У пользователя есть список его чатов. **Один чат = одна игра.**

В версии для ПК слева расположена сворачиваемая панель с чатами, далее сам чат
в стиле ChatGPT, а справа — область предпросмотра, занимающая не менее половины
экрана. В ней находится красиво оформленный макет телефона, реализованный
средствами HTML, CSS и TypeScript. Внутри телефона отображается игра,
в которую можно играть. Управление должно поддерживать телефон и ПК.

После доработки по промптам игра обновляется в этом же макете телефона.
Область с телефоном можно сворачивать и разворачивать, как правую панель в ChatGPT.

В чате есть кнопки режимов для улучшения генерации, например:

- «Для геймеров».
- «Для пенсионеров».
- «Для детей».
- Другие аналогичные режимы.

Режимы направляют работу LLM с учётом выбранной аудитории.
В мобильной версии в чате также есть кнопка открытия игры на весь экран.

В каждом чате предусмотрена кнопка **«Поделиться игрой»**, после нажатия которой
игра появляется в публичной ленте. Автор может задать ей название в ленте
и редактировать её.

После публикации автор может продолжать работу над игрой в том же чате,
но **публичная версия фиксируется на момент публикации**.
Чтобы обновить публичное состояние игры, автор нажимает кнопку **«Обновить»**.

Для каждого чата предусмотрена форма обратной связи, в которой пользователь
оценивает соответствие генерации своим ожиданиям. Если оценка отличается
от 5 баллов, он может выбрать причины, чтобы в дальнейшем модель учитывала
его приоритеты и улучшала результат. Например, если пользователь жалуется
на качество музыки в игре, при следующих генерациях больше внимания
должно уделяться музыке.

В первой итерации это реализуется без дообучения весов: backend хранит по одной
актуальной оценке каждой ревизии, вычисляет дефицит `5 − rating`, удваивает вес
отзывов текущего проекта и суммирует повторяющиеся категории. Последние 50
оценок пользователя и не более 10 очищенных комментариев образуют ограниченный
контекст предпочтений. Он передаётся и в спецификацию, и в генерацию, а его
точная версия сохраняется в `GenerationRun.feedback_snapshot`. Поэтому цепочка
«музыка 3/5 → улучшение → музыка 4/5 → дополнительное улучшение» накапливает
music priority, остаётся персональной и воспроизводимой. Реальное качество
музыки всё равно требует человеческой оценки: автоматические проверки
подтверждают работоспособность audio/game flow, но не художественное качество.

Модели подключаются через принадлежащий проекту интерфейс `ModelGateway`.
Основной коннектор использует OpenAI-compatible Responses API удалённого vLLM.
Адрес сервера, API-ключ и идентификатор обслуживаемой модели задаются через
окружение. OpenAI сохранён как необязательный резервный адаптер; переключение
провайдера не меняет продуктовый workflow, схемы спецификации и валидацию игр.

## Публичная лента, просмотр и доработка игр

Ключевая особенность проекта — главная страница авторизованного пользователя.
На ней расположен список публичных игр, которыми поделились пользователи.

У каждой игры сверху отображается название, ниже — небольшое демонстрационное
окно самой игры, в котором при наведении проигрывается предпросмотр.
Под ним расположены имя пользователя автора и число лайков.

У каждой игры есть кнопка **«Попробовать»**, открывающая интерфейс игры.
Поскольку игры предназначены для WebView, они должны быть адаптированы для телефона.

На ПК по центру страницы расположен красиво оформленный макет телефона,
также реализованный средствами HTML, CSS и TypeScript. Игра отображается
внутри его рамки. Управление поддерживает телефон и клавиши клавиатуры.
В углах интерфейса находятся две кнопки: слева **«Назад»**, справа **«Доработать»**.

Кнопка «Доработать» переводит пользователя в новый личный чат, где он может
изменять HTML-файл игры с помощью промптов.

На телефоне кнопка «Попробовать» открывает игру на весь экран.
Пользователь должен иметь возможность выйти из неё или перейти в чат для доработки.

При переходе к доработке публичной игры создаётся отдельный чат текущего
пользователя. Изначально история промптов в нём пустая, но HTML-файл игры уже есть.
Пользователь может отправлять новые промпты, улучшать игру и публиковать
результат от своего имени.

## Управление публикациями

**Удаление чата не приводит к удалению опубликованной из него игры.**

Реализация: удаление чата архивирует проект, скрывает его из личного списка и
закрывает приватные API, останавливая незавершённые генерации. Ревизии сохраняются
для публикаций и ремиксов. Удаление публикации — отдельное подтверждаемое действие;
оно отключает публичную ссылку, сохраняя личный чат и чужие ремиксы.

На главной странице авторизованного пользователя общий список игр можно
сортировать по популярности — числу лайков, по новизне и другим критериям.
Также пользователь может просматривать список своих опубликованных игр
и управлять им: менять названия и удалять публикации.

## Технологический стек

- **Сервер:** FastAPI, PostgreSQL 17+, Celery, Redis.
- **Клиент:** CSS, TypeScript, React.
