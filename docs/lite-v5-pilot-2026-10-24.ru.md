# Живой пилот Lite после обработки неполных исходников и ремонта модулей

24 октября 2026. Повтор тех же трёх запросов через GameForge API → relay → `qwen38`,
контракт v5, политика завершения 2. Первый набор сравнивается с
[предыдущим пилотом](lite-completion-pilot-2026-10-24.ru.md); второй — отдельное повторение.
Разрешение пользователя новое: не более 24 модельных вызовов и 90 минут суммарно.
Все операции, включая восстановление после локального сбоя, используют один журнал,
один срок и исходный потолок до четырёх вызовов на создание одной игры.

Пилот закрыт: **16 вызовов, 71 мин 18,0 с вместе с независимой оценкой**. От первого
Run до последнего решения — 69 мин 12,4 с, включая локальный сбой и паузы на проверку.
Оставшиеся 8 вызовов закрыты и не возобновляются. Активных или неизвестных вызовов
этого пилота нет; usage известен для всех 16: **52 588 input / 59 578 output tokens**.
Локальная цена relay настроена как нулевая: это не измерение стоимости GPU-инфраструктуры.
Ранее существовавший неизвестный расход аккаунта не изменился и не приписан этому пилоту.

## Главные наблюдения

**Проблема «игра уже работает, а генерация не завершается успехом» воспроизведена двумя
разными путями.**

1. В первом наборе второй ответ для крестиков-ноликов содержал рабочую игру, но только
   два regression-сценария. Контракт отверг ответ с `missing_effects` до создания Revision.
   Сырой ответ и usage сохранились приватно, однако эта реализация не попала в preview;
   следующий create заново сгенерировал код с синтаксической ошибкой. Независимые
   настоящие нажатия подтвердили чередование X/O, запрет занятой клетки, победы обоих
   игроков, ничью, сброс и блокировку ходов после конца. Отдельные реальные касания
   native-validator дали 4/4. Это **рабочий отклонённый исходник**, а не доставленный
   пользователю кандидат и не автоматическое принятие.
2. Во втором наборе первая версия крестиков-ноликов падала при победе. Первый ремонт
   устранил ошибку; две последующие сохранённые версии независимо играбельны. На каждой
   прошли 6/6 независимых сценариев с реальными касаниями. Приложение всё же остановило
   Run как `needs_attention / no_progress`: сценарий модели «победа» не составляет линию,
   а сценарий «ничья» приводит к настоящей победе X. Автоматический ремонт исходников
   пытается исправить расхождение с неверной игровой последовательностью.

Проверки приложения во время пилота не подменялись. Независимые сценарии — отдельное
измерение на том же hash HTML, без изменения кода, состояния игры или ручного принятия.

Повторный memory дополняет второй случай: после отклонённой заглушки корректирующий
create дал рабочую игру. В реальной партии проверены несовпадение с автоматическим
закрытием, сохранение совпавшей пары, поиск второй пары и видимая победа за три хода.
Его сценарии читают `moves`/`status` как глобальное состояние, хотя переменные закрыты
в функции; есть и неверные координаты карточек. Приложение корректно сохранило
`unverified` и не стало ремонтировать код из-за одной неопределённости. Это безопасное
завершение, но до автоматической готовности игра не дошла. Ручное принятие не выполнялось.

## Локальный сбой и границы сравнения

Первые grid/snake завершились `validator_unavailable`: отдельный native-preflight
прошёл, но существующий локальный worker работал без `VALIDATOR_BACKEND=native`.
Это ошибка подготовки текущего пилота. Примерно на 24-й минуте в локальном `.env`
явно выбран native, свои процессы приложения перезапущены. Исходные неудачные Run
сохранены в результатах; соединение восстановлено к прежнему relay job без повторной
отправки модели. Исходники генератора/валидатора и конфигурация GPU не менялись.

После этого выполнены model-free recheck для тех же кандидатов. Grid подтвердил
синтаксическую ошибку; snake получил `unverified / manual_verification`. Дополнительный
ремонт grid использовал единственный неиспользованный вызов из исходного потолка 4;
это операция восстановления, не новая независимая игра. Snake с неопределённым
отчётом на платный ремонт не отправлялся. Второй набор с самого начала использовал
корректный native backend.

Поэтому полное время первого набора нельзя выдавать за чистое замедление v5 относительно
v4. Модельные ответы первого набора, собственные ошибки кода и последующее восстановление
показываются отдельно. Вызов через relay включает доставку и ожидание; это не чистое
время GPU inference.

Во втором snake обе сохранённые версии показывают понятное начало, крупные кнопки и
змейку, но движения нет: `lastTime` сбрасывается каждый кадр, и `dt` не достигает
350 мс. Настоящий Start/Up и независимое ожидание подтвердили неподвижную голову
и отсутствие столкновения даже через 6 секунд. Ремонт оставил этот цикл прежним;
`no_progress` после двух вызовов здесь соответствует реальному дефекту. В первом
snake причина другая: CSS специфичность не позволяет скрыть одновременно видимые
начальный и конечный диалоги.

## Что изменилось относительно v4

В прошлом прогоне сохранённые grid/memory были HTML-заглушками, затем застревали
на `whole_file_patch` и `ambiguous_patch`. Теперь модель возвращает реальные модули,
и ограниченная замена файла действительно применяется с точным hash и неизменными
проверками. Но успешное применение не гарантирует правильный ремонт: восстановленный
grid получил новую ошибку кавычек. В первом memory все три ответа `replace_module`
повторили исходный файл байт в байт и были правильно отвергнуты как `no_changes`;
новый фиктивный кандидат не создавался.

Во втором memory живой первый ответ действительно получил `incomplete_sources`:
26 символов HTML, CSS и JS-комментарий вместо игры. Независимая упаковка показывает
пустую страницу, ноль Canvas и кнопок. Приложение не создало фиктивный кандидат,
сохранило ответ/usage и осталось в create в прежнем бюджете. Это наблюдение нового
маршрута обработки; само по себе оно не доказывает рост вероятности рабочей игры.

Предыдущий пилот независимо оценивал только сохранённые кандидаты, а отклонённые сырые
ответы не оценивал. Поэтому найденную сейчас рабочую сырую реализацию нельзя сравнивать
с якобы нулём таких ответов прежде. Равенство трёх промптов, порядка, рубрик, alias
модели и исходников provider/validator проверяется по паспортам; точные веса и sampling
relay не раскрывает. Это диагностическая малая выборка, не контролируемое A/B,
не сравнение с OpenAI, не p95 и не испытание физического WebView.

## Следующие изменения по результатам измерения

- Сохранять комплектный игровой код отдельно от пригодности сценариев: недостаток
  проверок должен вести к ограниченному восстановлению проверок на точном hash, а не
  к потере доступного preview и повторной генерации всей игры. Новая граница должна
  сохранять исходные требования и запрет ложного автоматического принятия.
- Различать дефект игры и логическую ошибку последовательности проверок. Для рабочего
  grid нужны настоящие победные/ничейные последовательности; менять игру под неверный
  oracle опасно. Простое расхождение `effect_mismatch` ещё не доказывает дефект кода.
- Давать модели фрагмент вокруг точной UTF-16-колонки ошибки. В memory ошибка около
  колонки 8058, а `source_excerpt` показывает начало единственной длинной строки.
  Три одинаковых `no_changes` также требуют остановки без ещё одного бесполезного
  повтора либо другого ограниченного способа восстановления.
- Разделить очередь model-free проверки и занятость провайдера: recheck grid/snake
  с нулём вызовов ждали примерно 419/422 секунды за memory inference.
- Проверять выбранный backend у реального worker перед новым пилотом. Отдельная
  успешная native-проба не доказывает, что worker использует его.

Эти выводы ещё не являются реализованными изменениями генератора. GPU-сервер не
администрировался, Codex не вызывался и его путь сохранён. Публикации и принятые версии
не изменялись; исходники и сырые ответы остаются приватно в `.data/lite-v5-pilot-20261024*`.

## Свидетельства и проверка отчёта

[Машиночитаемое свидетельство](evidence/lite-v5-pilot-2026-10-24.json) содержит ID/hash
кандидатов и рубрик, индивидуальные оценки, usage/времена/контракты вызовов, отдельные
бесплатные recheck, логический разбор ошибочных последовательностей grid и паспорт
39 файлов. Точные исходники, оригинальные ответы, закрытый журнал бюджета и снимки
экрана остаются в приватных артефактах. Проверены неизменность всех 39 файлов за время
пилота, совпадение исходников provider/validator с предыдущим прогоном, отсутствие
повторного учёта вызовов и полнота независимых оценок.

Перед подготовкой пилота паспорт расширен файлами восстановления/сериализации и
измерителя. Бюджетные регрессии измерителя — 7 passed; Ruff и проверка diff прошли.
Это дополнение метаданных, не изменение поведения генератора во время испытания.
Собственный временный диагностический сервер остановлен; четыре локальных процесса
GameForge оставлены работающими с native-validator. Физический мобильный WebView,
пользовательские малые правки и повторный платный прогон сюда не входят.
