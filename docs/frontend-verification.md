# Проверка интерфейса мини-игр

Дата: **18 октября 2026 года**. Ветка: `mini-games`.
Область: сопоставление [F01–F15](requirements.ru.md) с текущими `web/` и HTTP API,
компонентные проверки и отдельные реальные браузерные сценарии.

поставка описываются в основном [отчёте](verification.md).

## Читаемая типографика — 24 октября 2026

Вместо неподключённого Inter используется локально поставляемый **Manrope Variable**
из Google Fonts через `@fontsource-variable/manrope@5.3.0` (OFL-1.1). Текст интерфейса
имеет минимум **14px**, сообщения чата и ввод — **16px**. Проверены также мобильные
переопределения и подписи в декоративных блоках лендинга. Размеры в rem учитывают
увеличенный размер текста браузера; нижний предел закреплён в CSS-переменных.
Лицензия включена в production-сборку по `/licenses/manrope-OFL.txt`.

В Chromium на фикстурах API проверены **1440, 1280, 1100, 1024, 768, 760, 430, 390
и 320px**: настройки, чат с сообщениями, новый чат, лента с карточками, лендинг,
формы входа и оценки. Измерены вычисленные размеры видимого текста и переполнение
кнопок/страницы относительно заданного viewport. Обнаруженное переполнение шапки
чата на 320px устранено переносом действий; кнопка оценки доступна настоящему клику.
Карточки ленты, показатели в настройках и нижние действия preview переносятся по ширине.
Боковая панель расширена, межстрочные интервалы и контраст вторичного текста улучшены.

На всех проверенных размерах текст не мельче 14px, горизонтального переполнения
и обрезанных кнопок нет. Подтверждены загрузка Manrope, обе темы и отсутствие
обращений к внешним шрифтовым сервисам. Снимки находятся локально в игнорируемой
`.data/typography-ui-qa/`. Это проверка оболочки на тестовых данных, без LLM и запуска
настоящего игрового кода; типографика ранее созданных игровых артефактов не меняется.
Все **72 компонентных теста**, ESLint/Prettier и production-сборка прошли.

## Повторные запросы, состояния и бюджет

- `api.ts` не повторяет мутацию автоматически после потери соединения. При повторном
  нажатии Studio использует прежний idempotency key для того же payload. Изменённый
  запрос получает новый ключ. Созданный чат сохраняется в состоянии даже при потере
  ответа первого запуска; повтор не создаёт новый платный запуск в другом чате.
- Кнопки продолжения, отмены и ручной приёмки следуют серверным `can_*`.
  Для `unknown` нет автоматического повтора. При `can_retry_unknown` доступен новый
  запрос только после отдельной отметки о дополнительном расходе; backend требует
  `accept_unknown_cost:true`, сохраняет прежнюю неизвестную сумму и отклоняет устаревшую
  базовую версию. Повтор того же HTTP-запроса использует тот же idempotency key.
  Сверка неизвестного исхода выполняется оператором, а не скрытым повтором frontend.
- Ручная приёмка предлагается только для `unverified`. UI показывает именно кандидат,
  просит лично проверить управление, основное действие и исход; отправляет явное
  `{confirmed: true}`. `failed` и инфраструктурная ошибка не принимаются этим действием.
  Статус `manual` не выдаётся за автоматическую приёмку.
- Нет выдуманного процента прогресса. SSE показывает сохранённые события; GET состояния
  каждые 2,5 секунды, пока запуск активен, служит резервным каналом. Sidebar проверяет
  активные чаты раз в 5 секунд. После окончания активный polling прекращается.
- Общий бюджет разделён на подтверждённый расход, активный резерв, неизвестный расход
  и доступную сумму. UI явно поясняет API-эквивалент подписки. Модель с `priced:false`
  недоступна в селекторе; backend дополнительно отказывает до обращения к провайдеру,
  если тариф не настроен. Эта проверка не подтверждает корректность самих численных тарифов.
- При независимом ревью обнаружено отставание суммы в настройках от карточки запуска.
  **Исправлено:** при открытии настроек и однократно при появлении конечного состояния
  запуска обновляется session; постоянного дополнительного polling нет. Два новых
  regression-теста проверяют актуальные суммы и отсутствие повторных/модельных запросов.
- Также обнаружено, что продолжение могло брать модель по умолчанию вместо модели
  исходного запуска. **Исправлено в backend:** по умолчанию наследуются
  `continued_from.model` и `continued_from.provider`. Добавлен
  `studio/tests/test_domain.py:test_continue_preserves_selected_provider_and_model`;
  backend-агент подтвердил 44 прошедших теста. Этот результат не входит в 32 frontend-теста.

## Настоящий проигрыватель, экспорт и приватность

Проверен точный кандидат **`e02f3375-ac22-4454-8ea7-c017181f3455`**, «Пять звёзд»,
в чате **`7f57e083-5f4b-4e48-99b8-50707810f8c5`**.

   состояние не изменялось, события не подменялись `dispatchEvent`.
3. Полный экран растягивает существующий iframe. Его идентичность до/после сохранена;

6. Гость не получает приватный iframe, revision/source/export отвергнуты сервером.
7. SHA-256 скачанного HTML совпал с `artifact_hash`. Экспорт открыт через `file://`
   при offline-сети: canvas и начало игры работают; HTTP/HTTPS-запросов не было.

При этом сохранённые тестовые сценарии этой игры были ошибочными: `x:0,y:0` у селектора
кнопки целились в верхний левый угол скруглённой поверхности, а сценарий исхода лишь
начинал игру и не собирал звёзды. Это объясняет расхождение автоматической проверки
с реальными действиями. Результат ручного исследования **не менял** статус приёмки и
не подменяет последующее исправление сценариев генератором.

## Аналитика как явно обозначенный бонус

`SyntheticAnalytics.tsx` показывает три **вымышленных** показателя, помеченных
«ДЕМО · СИНТЕТИЧЕСКИЕ ДАННЫЕ», с явным текстом, что это не данные игроков.
Единственная рекомендация объясняет связь размера touch-зоны с промахами. Только
явное действие пользователя сохраняет её через preferences API; она остаётся
редактируемым пожеланием, не жёстким жанровым шаблоном. Лимит десяти пожеланий не
обходится и прежние notes молча не удаляются. Компонентные тесты проверяют payload,
сохранение прежних пожеланий и отсутствие вызова генерации. В тестовый настоящий аккаунт
рекомендация при этой проверке не добавлялась, чтобы не менять условия модельного пилота.

## Что этот отчёт не подтверждает

- Скорость или успешность генераций разных жанров, устойчивый p95, качество всех
  адаптаций аудитории — это предмет модельного пилота, а не результата Vitest.
- Физический Android/iOS WebView, Safari, реальные мобильные устройства и конкурсный хост.
  Отдельное испытание доступного macOS WKWebView описано в [своём отчёте](wkwebview-smoke.md)
  и не является проверкой мобильного приложения Билайна.
- Развёртывание на `digsy.ru`, TLS и доступность внешнего сервиса.
- Работу настоящей локальной LLM: доступен адаптер, но модель пока не предоставлена.
- Полный аудит доступности по WCAG или полный security audit. Проверены конкретные
  границы iframe, отсутствие Cookie и гостевой доступ; это не универсальное доказательство.
- Полный браузерный create → edit → publish → remix на всех жанрах одним frontend-сеансом.
  Покрытие разделено между компонентными, backend, контейнерными и реальными модельными
  испытаниями; эти категории нельзя складывать в фиктивный единый процент успеха.
- Сохранение игрового состояния при сворачивании всей панели preview: сейчас панель
  размонтирует iframe и при раскрытии игра начинается заново. Fullscreen сохраняет его.
  Hover-preview снимается при уходе указателя; отдельной обработки скрытия вкладки и
  выхода карточки за границы экрана пока нет. Сохранённые версии/задания от этого не меняются.
