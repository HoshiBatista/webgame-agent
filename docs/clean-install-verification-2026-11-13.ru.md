# Чистая установка и исправление тестов — 13.11.2026

Исходная проверка ветки `mini-games` на базе `134e6a3` с исправлениями. Результаты
переноса поверх актуального `main` приведены отдельно ниже. Рабочая БД,
облако, GPU, доступы и пользовательские артефакты не изменялись. Все модельные ответы
в тестах — фикстуры и локальные имитаторы; реальных вызовов модели нет.

## Исправления

- В `requirements-dev.lock` отсутствовал Pillow, хотя приложение и тесты используют
  `PIL`. Добавлена production-версия `12.3.0` без обновления остальных зависимостей.
- Проверка упаковки теперь сопоставляет runtime-зависимости из `pyproject.toml`
  с обоими lock-файлами, включая версии и необходимые extras. До исправления она
  воспроизводимо отклоняла dev-lock из-за отсутствующего Pillow.
- Тест vLLM больше не предполагает, что актуальные инструкции и схема умещаются
  в прежний консервативный бюджет 32K. Используется тестовый контекст 64K; увеличение
  ответа почти до его размера по-прежнему отклоняется в conservative и допускается
  в server без изменения сообщений, схемы или обрезания запроса. Проверяются все
  три JSON-режима. Настройки реального провайдера не менялись.
- Фикстура Run для проверки hash промпта задаёт обязательное `allow_model_calls`.
  В `main` эти два теста уже исправлены: при переносе сохранены существующие
  контролируемые сообщения/схема транспортного теста и поле Run без дублирования.
- Имитатор relay явно закрепляет поддерживаемый им `json_schema` и серверную
  проверку контекста. Раньше эти условия неявно наследовались из частной `.env`.
- Тест переименования при ручном принятии использует фиксированную identity
  имитатора валидатора, а не обращается к локальному Docker/native backend.
  Проверки принятия в приложении не ослаблялись.
- В CI и инструкции установки добавлен `python -m pip check`.

## Проверенная установка

Ubuntu 24.04 / WSL2, Python **3.12.3**, PostgreSQL **18.7**, Node **24.21.0**.
Node 22 из конфигурации CI в этом локальном прогоне не проверялся.

Созданы отдельные пустые Python-окружения вне репозитория. Dev-окружение установлено
только из исправленного `requirements-dev.lock`; полный resolver с зафиксированными
версиями подтвердил тот же набор из **63 пакетов**. `pip check` успешен.

Production-окружение установлено через pip только из `requirements.lock`, затем
получило собранный wheel с `--no-deps`. `pip check` успешен. Из каталога вне репозитория,
с Python `-I`, проверены импорты Pillow и генератора, пять JS/CSS runtime-ресурсов,
hash политик и упаковка тестового ответа в автономный HTML. Это проверка поставки
Python-пакета; тестовый ответ не считается настоящей генерацией.

PostgreSQL запущен временно в отдельном каталоге `/tmp`, без системной установки.
Проверены миграции пустой БД до `0024`, Django `check` и отсутствие новых миграций.
Два запуска bootstrap подтвердили сохранение исходного пароля администратора.
Локальный Gunicorn по HTTP вернул health, собранный интерфейс и гостевую сессию
с provider=fake. Redis/worker и полный путь новой игры этим HTTP smoke не проверялись.

Frontend заново установлен через `npm ci`; lint, **150 тестов** и production build
прошли. Ruff и mypy по `generation`/`validation` (**51 модуль**) прошли.

Полный backend-прогон на чистом Python 3.12 и временном PostgreSQL 18:
**1223 passed, 164 deselected за 91,33 с**. Исключены browser/native_browser/live.
Перед финальным прогоном исправлены четыре исходных падения и ещё 13 падений,
найденных при первом запуске с БД без частной `.env`. Целевые relay/compact/title

## Команды повторной проверки

Требуются отдельная локальная PostgreSQL 18+ БД с правом создавать тестовую БД,
приватный `DJANGO_SECRET_KEY` и `GAMEFORGE_PROVIDER=fake`. Параметры подключения
задаются через `DATABASE_URL`; тесты не требуют доступа к настоящей модели.

```sh
python3.12 -m venv .venv
.venv/bin/python -m pip install -r requirements-dev.lock
.venv/bin/python -m pip check
.venv/bin/ruff check gameforge studio generation validation scripts tests
.venv/bin/mypy generation validation --ignore-missing-imports
.venv/bin/python manage.py check
.venv/bin/python manage.py makemigrations --check --dry-run
.venv/bin/pytest tests studio/tests -m 'not browser and not native_browser and not live'
npm ci --prefix web
npm run lint --prefix web
npm test --prefix web
npm run build --prefix web
```

## Ограничения

Docker недоступен в текущей WSL-интеграции, контейнерная сборка не проверялась.
`scripts/native.py prepare` скачал закреплённый Chromium 145 / revision 1208,
но проба ОС-изолированного браузера остановилась из-за отсутствующих системных
`libnspr4.so`, `libnss3.so`, `libnssutil3.so`. Перед браузерными тестами нужен штатный
`python -m playwright install-deps chromium` из инструкции нативной установки.
Браузерная проверка и физический WebView в этот результат не входят; запуска без
изоляции не было. Удалённый CI не запускался и не объявляется успешным.
