# Параллельная генерация Pro — 27.10.2026

> Исторический отчёт о первой поставке. 29.10 владелец увеличил предел с 2 до 100;
> актуальные настройки и границы проверки — в [подключении Pro](codex-api.ru.md#параллельность).

По запросу владельца Pro получает два параллельных места, общих для Mac и облачного
GameForge. Оба места могут занимать игры одной установки или по одной с каждой.
Дополнительные игры остаются в сохраняемой очереди. Один чат по-прежнему содержит одну
игру и один активный Run. Лимит Lite/GPU и прямого локального CLI не повышается.

## Устройство

В отдельном Codex Worker один диспетчер держит прежнюю пожизненную блокировку БД.
Внутри него ограниченный пул: каждой работе принадлежат отдельные процесс app-server,
временный каталог, thread/turn, отмена, checkpoint, usage и квитанция. Учётная запись
Codex остаётся общей; параллельность не создаёт дополнительных квот подписки.
Освободившееся место сразу получает следующее FIFO-задание, не дожидаясь медленного соседа.

`CODEX_WORKER_CONCURRENCY` задаёт общий предел, допустимо 1–4; по умолчанию без env — 1,
для текущего VPS выбран 2. API и executor читают одно значение из Compose environment.
Health показывает `concurrency` и `active_jobs`. Решение о claim атомарно внутри SQLite,
вместе с проверками drain/attention. Нельзя масштабировать контейнер executor копиями:
блокировка остаётся единственной, и восстановление выполняется ровно одним диспетчером.

После unknown новые отправки блокируются. Уже отправленные соседние запросы могут
сохранить результат. Подготовленный, но ещё не отправленный запрос возвращается в
очередь с прежним UUID. Drain проверяется повторно перед durable submission marker;
отмена до отправки остаётся отменой. При падении диспетчера блокировка удерживается
всеми ещё живыми дочерними Codex-процессами. Восстановление начинается после их выхода:
все отправленные незавершённые задания становятся unknown с сохранёнными фрагментами
и usage, ни одно из них не запускается снова.

В GameForge `GAMEFORGE_CODEX_API_CONCURRENCY=2` относится только к `codex_api`.
Занятость — объединение обрабатываемых Run и ожидающих Invocation, включая отмену до
получения квитанции; один Run считается один раз. Проверка и резерв бюджета выполняются
под общей блокировкой Budget в PostgreSQL. Получение уже принятого удалённого задания
допускается и после снижения лимита. Любой следующий новый модельный шаг вновь проверяет
места: при нехватке сохраняет план/кандидат и возвращается в очередь без расхода попытки.
Celery имеет четыре потока для двух Pro, Lite и коротких служебных задач.

Протокол Codex не менялся, версия CLI осталась закреплённой. Процессы используют
прежний профиль без инструментов. Структура thread/turn и адресная отмена сверены с
[официальной документацией App Server](https://learn.chatgpt.com/docs/app-server).
Документация не является доказательством пропускной способности конкретного аккаунта.

## Проверки и ревью

Регрессии Codex Worker запускают реальный локальный HTTP и независимые тестовые
процессы вместо модели. Барьеры позволяют проверить фактическое перекрытие двух turns,
разные PID/cwd, результаты в обратном порядке и заполнение освободившегося места.
Проверяются общий предел, два владельца/один владелец, отсутствие доступа к чужому UUID,
повтор PUT без нового turn, drain, адресная отмена и авария двух процессов.

В GameForge проверяются два одновременных задания и третье ожидающее, сохранность игр,
отмена и освобождение мест, получение ответов после снижения лимита, ожидание между
планом и реализацией, атомарность допуска из шести потоков, прежние лимиты Lite/CLI
и запрет двух активных игр в одном чате. API-тесты используют независимый двойник.

Саморевью отдельно проверяет гонки допуска/отмены, владение блокировкой, потерю процессов,
снижение лимита, резервирование бюджета и отсутствие новых прав у модели. Независимый
второй рецензент не привлекался. Реальных модельных вызовов в этой поставке не делаем:
прежний лимит 2/2 закрыт. Живая параллельность OpenAI и игровой цикл под нагрузкой
требуют отдельного согласованного пилота.
