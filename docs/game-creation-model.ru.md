# Как будет создаваться игра в новой конкурсной версии

18 октября 2026 года. **Это модель запланированной реализации. Новый код ещё не написан.**
Подробности — в [архитектуре](architecture.md), статус — в [плане](development-plan.md).

1. Пользователь открывает чат и кратко описывает мини-игру. Аудитория и пожелания
   аккаунта дополняют запрос. Название модель предлагает сама, если оно не указано.
2. Один запрос модели возвращает код, короткий замысел и конкретные действия для проверки.
   Отдельных платных шагов планирования и пересогласования по умолчанию нет.
3. Приложение сохраняет кандидат, собирает HTML и проверяет его в изолированном браузере:
   загрузку, управление, основной эффект, игровой исход и телефонный интерфейс.
4. Успех сразу становится доступной рабочей версией. Ошибки возвращаются одним пакетом
   на одну автоматическую точечную правку, после которой проверяется новый кандидат.
5. Если проблема осталась или модель недоступна, сохраняются результат и объяснение.
   Пользователь может продолжить с этого места. Бесконечного фонового исследования нет.
6. Для «перекрась», «увеличь кнопки», «добавь два уровня» модель выдаёт патч к сохранённой
   версии. Неизменённый код сохраняется; пересборка HTML выполняется локально.
7. Чат хранит версии. «Поделиться» фиксирует выбранную проверенную версию; последующие
   правки её не меняют. «Обновить» публикует новый снимок отдельным действием.
8. «Доработать» публичную игру создаёт собственный чат с копией опубликованного снимка
   и пустой историей промптов. Удаление исходного чата не удаляет публикацию.

Готовность определяется работающим результатом и проверками, а не окончанием бюджета.
Проверки принадлежат механике игры: нет общей обязательной кнопки, счётчика или требования
«каждое нажатие меняет пиксели». Неподтверждённое условие показано явно; ручная проверка
не выдаётся за автоматическую.

Сначала генерация вызывается через локальный Codex-login. Затем тот же процесс работает
с vLLM через API. Смена провайдера не меняет чаты, историю, формат патчей и публикации.
Целевое время — десятки секунд на игру и секунды на небольшую правку; его ещё предстоит
измерить на реальных моделях. В расширенном GamesForgeEx действует другая архитектура.
