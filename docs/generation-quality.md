# Качество генерации: первый этап

25 октября 2026 года. Изменения в ветке `mini-games`, без новых платных вызовов.

## Основания

В сохранённом [пилоте](verification.md) автоматически приняты 3 из 5 созданий.
Обнаружены перекрывающие начало игры панели, устаревшие копии наблюдаемого состояния,
ошибки клавиатуры и потери фокуса, неверные сценарии ввода. Сетевые обрывы и
недоступность браузера — отдельные инфраструктурные причины; их не исправляют
переписыванием игры. Эти исторические результаты не являются замером нового промпта.

## Что изменено

- Промпт задаёт понятную цель, начало, обратную связь, достижимый исход и повторный
  раунд. Уточнены визуальная иерархия, размер touch-целей, работа overlay, resize,
  devicePixelRatio, координаты и очистка удерживаемого ввода. Общий движок и каталог
  жанров не добавлены; правила и оформление генерирует модель.
- Полный набор требует мобильного старта и сценария `control` с касанием без
  клавиатуры. Проверка действует после объединения с унаследованными сценариями,
  внутри валидатора и при приёме его успешного отчёта. Отдельная desktop-проверка
  клавиатуры разрешена. Одна проверка открытия меню не доказывает исправность механики:
  выбор содержательного эффекта остаётся частью контракта модели и анализа результатов.
- Добавлена категория `restart` с реальным вводом. Промпт требует проверять повтор,
  если он есть: сначала прогресс/исход, затем настоящий повтор и новая игра. Наличие
  replay не определяется автоматически по исходникам; одна схема не гарантирует,
  что модель включила все нужные сценарии. При коррекции существующий сценарий
  наследуется, его требование нельзя незаметно ослабить.
- Автоправка получает действия и наблюдения из отчёта текущего кандидата, а не только
  текст ошибки. Контекст ограничен 24 КБ UTF-8; слишком большие значения и пропущенные
  факты отмечаются, полный отчёт сохраняется. Скриншоты не передаются текстом.
- Один основной вызов и максимум одна автоправка сохраняются. Изоляция, отмена,
  неизвестный расход и последняя рабочая версия не меняются.

## Проверки

Локальная регрессия без PostgreSQL, браузерного контейнера и настоящей модели:

```sh
.venv/bin/pytest tests -m 'not browser and not live'
.venv/bin/ruff check gameforge studio generation validation scripts tests
.venv/bin/mypy generation validation --ignore-missing-imports
.venv/bin/python manage.py check
```

Добавлены отрицательные сценарии desktop-only, mouse-only, keyboard-only и смешанного
touch+keyboard вместо самостоятельного мобильного управления; проверка слияния правок;
отклонение неполных успешных отчётов обоих транспортов; соответствие фактов кандидату,
ограничение контекста и исключение постороннего отчёта из автоправки.
Браузерный тест правильного и сломанного рестарта добавлен в `tests/test_validation.py`.
Для его выполнения требуется пересобранный изолированный validator:

```sh
VALIDATOR_CONTAINER=gf-mini-validator-tests sh scripts/validator-start.sh
VALIDATOR_CONTAINER=gf-mini-validator-tests .venv/bin/pytest tests/test_validation.py -m browser
```

В текущей WSL-среде Docker и PostgreSQL недоступны. Новый браузерный тест и
`studio/tests` здесь не выполнены. Локальные проверки использовали временное Python
3.13 окружение с зависимостями из `requirements-dev.lock`.

Фактический результат: **130 passed, 12 deselected** за 7,30 с. Ruff, Mypy
(16 модулей), Django `check` и `git diff --check` прошли. Форматирование затронутых
модулей и нового тестового файла проверено Ruff. `uv build --out-dir
/tmp/gameforge-mini-analysis-dist` успешно собрал sdist и wheel; это проверка
Python-пакета, не контейнерной поставки и не запуска игры.

## Оптимизация инструкций по операциям

Вместо единого промпта из 9 969 символов используется общее ядро, правила проверок
и инструкции только текущей операции. Стабильный общий префикс сохраняется.

| Операция | Символов в системных инструкциях | Сокращение |
| --- | ---: | ---: |
| Создание | 5 291 | 46,9% |
| Правка | 6 128 | 38,5% |
| Исправление | 6 272 | 37,1% |

Это размер инструкций, не токенов и не всего запроса: схема, пользовательский запрос,
актуальные исходники и факты проверки учитываются отдельно. При vLLM в режиме
`json_object`/`none` схема дополнительно включается в системное сообщение адаптера.
Hash выбранных инструкций записывается для каждой операции, схема имеет отдельный hash.

Модель получает ориентир 4–6 содержательных сценариев, до 12 при необходимости.
Количество не служит основанием удалить важный эффект или унаследованную регрессию.
Убраны повторяющиеся пояснения и не относящиеся к операции инструкции. Сохраняются
цель, правила, законченная механика, оформление, touch/keyboard, обратная связь,
достижимый исход, повторный раунд и все ограничения безопасности. Сокращение не задаёт
жёсткий лимит длины кода и не разрешает пропускать функции ради скорости.

Регрессии проверяют выбор операции, изоляцию инструкций от пользовательских данных,
hash в запросе и передачу нужного промпта через Codex и три JSON-режима vLLM.
Это проверки адаптеров на управляемых ответах, не доказательство качества новой игры.
Ускорение и художественное качество нового промпта на модели ещё не измерены.

После оптимизации выполнен полный локальный набор `pytest tests -m 'not browser
and not live'`: **155 passed, 12 deselected** за 11,90 с. Ruff lint, проверка
форматирования изменённых модулей промпта/сборки запроса и новых тестовых файлов,
Mypy, Django `check`, `git diff --check` и повторная сборка sdist/wheel прошли.
`studio/tests` и браузерные проверки по-прежнему требуют недоступных здесь PostgreSQL
и Docker; изменение DB-теста записи hash не выдаётся за выполненный интеграционный прогон.

## Как измерить результат на модели

После выделения нового бюджета повторить пять запросов и две правки из
`scripts/live_eval.py` на одной модели и прогретом стенде. Сохранить hash промпта,
схемы и реализации проверок; учитывать ошибки, продолжения и все вызовы. Сравнивать:

- долю автоматически принятых созданий и правок, без ручного подтверждения;
- долю операций с автоправкой, причины дефектов и неизвестные исходы;
- полное время до playable-версии, время модели/проверки и известный/неизвестный расход;
- ручную оценку каждого результата: понятность цели и управления, читаемость на
  телефоне, обратная связь, согласованность оформления и работоспособность повтора.

Это малый пилот, не доказательство устойчивого p95. Новый промпт пока не проверен
на реальной модели: улучшение художественного качества и процента успеха не измерено.

## Интеграция с v8 и текущим интерфейсом

Удалённая ветка до `0c498b1` объединена с локальной `188c281`, включающей поставку
v8 `7400bdb`. Сохранены изменения названий чатов, рекомендации игр во время генерации,
sidebar и локальный разделитель профиля. Действует только контракт v8: описанная выше
поддержка v2–v4 относится к прежнему снимку и в итоговое слияние не возвращена.
Лимит ремонта остаётся закреплённым в Run, до трёх попыток, с прежним учётом unknown.

Восстановление сценариев теперь понимает новые findings отсутствующего мобильного
старта/управления. Если существующие условия проверялись только на desktop, приложение
добавляет мобильные сценарные требования с отдельными ID, сохраняя исходные условия.
Смена сценариев не меняет код и требует подтверждения; доказанный runtime-дефект
не переопределяется ошибкой проверки. При нехватке места в лимите 12 сценариев
исходные проверки не удаляются. Эти взаимодействия покрыты новыми регрессиями,
включая два полных прохода через изолированный Chromium с fake-провайдером.

Миграция `0013_merge_titles_and_compact` объединяет независимые ветви
`0011_chat_titles` и `0012_compact_generation_profile`, без новых изменений данных.
Граф проверен на тестовой PostgreSQL; к рабочей БД миграции не применялись.

Проверки слияния без inference:

- Backend: **605 passed**, browser/live исключены.
- Native browser: первый проход **80 passed / 4 failed**. Все четыре несовпадения
  оказались прежними ожиданиями мобильного покрытия. Для pointer-сценариев теперь
  выполняются реальные touch-действия; тест отпускания клавиши проверяет успешные
  факты отдельно от неподтверждённого сенсорного управления. Повтор всех трёх
  затронутых файлов: **42 passed**, включая все четыре исправленных случая.
- Два Docker-only теста Unix-транспорта и снимков состояния исключены из native
  команды; в этой интеграции они не выполнялись.
- Frontend: **109 passed**, lint и production build прошли.
- Ruff, Mypy (34 модуля), Django check, makemigrations --check --dry-run и
  git diff --check прошли. Codex проверен имитаторами в общем наборе, без turn/start.

Поставка R3 из отдельного плана не реализовывалась. Облачное обновление отложено
по запросу пользователя; приложение на VPS и GPU-сервер не изменены.
