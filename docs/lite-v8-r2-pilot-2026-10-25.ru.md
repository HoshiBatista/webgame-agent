# Повторный живой пилот Lite после ревью v8

25 октября 2026. Новый отдельно согласованный бюджет — до **48 вызовов / 180 минут**.
Пилот закрыт на **23 вызовах за 64 мин 25,9 с**. Остаток **25 вызовов закрыт**.
Начало `2026-10-25T11:29:59.346Z`, закрытие `12:34:25.262Z`
(14:29–15:34 по Москве). Нового неизвестного расхода **0**.

Исправленный lines дал исполняемые исходники во всех трёх задачах. Контрольное
восстановление проверок full и compact прошло по **3/3**, без изменения кода.
Автоматически готовых новых игр по-прежнему **0**. Рост качества генерации не доказан:
основное string-сравнение снова дало **2/6** базово играбельных игр.

## Условия

Использованы существующие локальное приложение и API реле, Lite `qwen38`.
GPU-сервер не обследовался и не администрировался; облачного deployment нет.
Исходник адаптера и авторизация Codex не менялись, вызовов Codex **0**.
Установленный `codex-cli 0.164.0-alpha.11.1` проходит существующую проверку версии.

Весь пилот прошёл на одном неизменном manifest **47 файлов**. Архив исходников,
hash контроллера, старт, пределы и каждая квитанция сохранены отдельно от первого
пилота в `.data/lite-v8-r2-20261025*`. Старое разрешение 48/180 не возобновлялось.
Текущий production validator —
`f1e9a1e841963a881b3177fdb55ff63369c319e86cd860748e98a975cfa379e0`,
Chromium 145.0.7632.6, mobile 390×844 / desktop 1280×800.

Перед стартом прошли **16** целевых регрессий lines/observations/merged manifest,
Django check и проверка отсутствия новых миграций. Полный набор прошлого ревью
повторно не запускался: продуктовый код после него не менялся.

В основной серии — те же grid/snake/memory и та же закрытая рубрика
start/control/outcome/mobile. Порядок заранее сохранён: lines-grid, full-grid,
string-grid, full-snake, lines-snake, string-snake, string-memory, full-memory,
lines-memory. Предел каждого создания — до четырёх вызовов в общем бюджете.
После 150 минут новые отправки запрещены, 180 минут — жёсткая граница опыта;
все запросы завершились значительно раньше.

Независимая оценка использует реальные touch/mouse/keyboard события, собственные
plain-state поля, видимый DOM и чтение пикселей Canvas. Закрытые переменные и getters
не выполняются, игровые состояние/время/RNG не подменяются. Для случайной memory
оценщик выбирает реальные действия по доступному порядку или открытым счётчикам.
Это ОС-изолированный Chromium, не физический телефон. Временные копии оценщика имеют
отдельные hashes; они не подменяют production receipts и не участвуют в принятии игры.

«Играбелен» здесь сохраняет базовую рубрику прежних опытов. Дополнительные дефекты

## Исправленный lines

Все фактически отправленные схемы совпали со схемами зафиксированной реализации.
В запросах lines передан ASCII-pattern `^[^\r\n]*$`. Все три материализованных
`game.js` точно равны LF join принятого `source_lines`, содержат скобки и исполняются.
Ни дописывания скобок, ни изменения кода оператором не было. Первый lines-grid имеет
87 открывающих и 87 закрывающих круглых скобок и независимо прошёл 9/9 сценариев.

Прежняя систематическая потеря скобок в этом прогоне не повторилась. Это живое
подтверждение работоспособности исправленного формата на этих задачах; версия и
внутренняя причина серверного декодера по-прежнему не устанавливались.

У первых lines-ответов snake и memory возникло другое отклонение: отсутствовали
обязательные **status, summary, world**, хотя отправлено `json_schema`, `strict=true`
и эти required-поля. Usage известен, finish_reason=stop. Следующие create-ответы
прошли контракт. Поэтому нельзя утверждать, что сервер всегда соблюдает всю схему;
данные подтверждают исходящий контракт и полученное нарушение, но не его внутреннюю
серверную причину. GPU-сервер для её поиска не обследовался.

## Восстановление проверок без перегенерации

В естественных созданиях check_repair часто давал лишь частичный результат.
Lines-grid улучшился с 1/3 до 2/3 подтверждённых фактов, full-grid — с 1/7 до 4/7.
Ошибочные checkpoints, маршруты победы и непригодные наблюдения остались.
Для full-snake и string-memory ответ unchanged содержал непустые сценарии и был
отклонён как invalid_unchanged. Автоматическое принятие не состоялось.

Дополнительно выполнены два контрольных опыта на заведомо играбельном неизменном HTML:

| Контроль | Вызовы | Результат |
| --- | --- | --- |
| Compact, точный прежний grid `b1a97df9…`, неверное observation `missing_cell` | **1 check_repair** | Исправлено на реальное `b.0`; **3/3** факта прошли. Требования и все исходники сохранены |
| Full, новый проверенный grid `f0235220…`, неверный selector `#missing-turn` | **1 check_repair** | Исправлено на `#turnSym`; **3/3** факта прошли. Требования и все исходники сохранены |

Оба результата имеют unverified только из-за `check_suite_revised`: изменённые
сценарии требуют явного подтверждения. Подтверждение и публикация не выполнялись.
Это успешное восстановление в двух конкретных контролях, а не оценка общей частоты
успеха. Прежний compact-контроль на том же HTML не восстановил полный набор условий;
в этой новой попытке восстановил.

Подготовительные recheck имели **0 inference**. Первый контролирующий скрипт прекратил
ожидание через 100 с, но сам Run не отменялся и не дублировался. Его проверка позже
завершилась с тем же ID. Причина ожидания — действующий provider_concurrency=1:
даже check-only Run ждёт активную генерацию того же провайдера. Это задержка очереди,
а не зависший запрос модели.

## Два подтверждённых дефекта приложения

**1. Ошибка сценария выдаётся за недоступность валидатора.** У string-snake один
сценарий содержит ожидания 2500+2600+2600+2400 = **10 100 мс** при пределе 10 000.
`validation/contracts.py::browser_watchdog_seconds` бросает ValueError ещё до запуска
браузера, а service превращает его в infrastructure_error / validator_unavailable.
Обязательные artifact gates для этого кандидата не выполняются.

API recheck `0bdfac8d…` сохранил тот же hash и сделал **0 вызовов модели**, но повторил
ошибку. Сам браузер исправен: независимые короткие сценарии запустились и выявили
настоящий runtime-дефект игры. Следующее исправление должно сохранять bounded watchdog,
помечать чрезмерный сценарий как invalid_check и всё равно проверять артефакт.
Нужна регрессия на 10 100 мс и контроль неизменности кода/отсутствия inference.

**2. Compact-runtime не рисует асинхронные изменения без update.** В
`generation/runtime/compact-v1.js::tick` paint находится внутри ветки наличия
необязательного `game.update`. Lines-memory меняет состояние в setTimeout, а Canvas
остаётся прежним до следующего ввода.

Это отдельно воспроизведено **без модели** на минимальном модуле: после таймера
`on=true`, пиксель остаётся синим; следующий реальный tap делает тот же пиксель красным.
Игра и runtime не изменялись. Исправление должно согласовать обещанный общий render loop
с необязательным update; регрессия обязана проверять реальный пиксель после таймера.
Даже после этого исправления логические ошибки пар в сгенерированной memory останутся.

Оба дефекта обнаружены и подтверждены в пилоте, **в этом прогоне не исправлялись**:
исходная версия оставалась неизменной для сравнения. Отдельно стоит освободить check-only
проверки от модельного слота, сохранив собственный предел нагрузки браузера.

Ещё одно наблюдение для следующей проверки prompt: compact repair передаёт source,
но также пустое files. Один ответ проигнорировал 5041 байт source и отказался из-за
«отсутствующих исходников». Удаление лишних полей и более короткий контекст — гипотеза
для отдельной пробы, не доказанное решение слабого следования инструкции.

## Завершение, учёт и решение

Все **9 новых созданий** получили терминальный результат; все **23** модельных вызова
имеют квитанции и известный usage: **19 settled, 4 failed по контракту**, finish_reason
stop у всех 23. Это не 19 успешных игр. Известные totals — **66 614 input / 49 374 output**.
Новых unknown, reserved/sent и активных Run нет. Сбои завершения прошлого пилота здесь
не воспроизвелись; их постоянное устранение этим не доказано.

Все **196 прежних Invocation целиком** совпали по hashes, пароль пользователя сохранён.
Все **11 исторических unknown**, включая два прошлого пилота, сохранены отдельно.
Учёт приложения и его настроенный тариф не доказывают внешнюю стоимость исполнения;
предел этого опыта считался по вызовам и времени.

Рабочая версия генератора и валидатора в ходе пилота не менялась; Codex сохранён.
Компактный профиль остаётся выключенным по умолчанию. Сначала следует исправить
два подтверждённых дефекта проверки/render loop локальными регрессиями, затем
проверить короткие сценарии восстановления. Расширение архитектуры до planner/GameSpec
по этим данным не требуется. Для нового оплаченного сравнения нужен отдельный бюджет:
неиспользованные 25 вызовов этого опыта закрыты.
